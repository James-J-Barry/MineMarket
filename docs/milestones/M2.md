# M2: Almanac Lectern and Drafting Table

Source: `docs/design.md` → "The Almanac Lectern: upgrades, guides and quests", "Crafting: the Drafting Table
and components" and "Information as progression".
Goal: the player can **buy upgrades with dollars**, read short guides, complete the first quests, and **craft
what they unlocked at a Drafting Table** using components bought from the Dealer. Everything per-player,
persistent, and testable without a client.

**Unlock rule (decided):** an unlock is never a single item that can be lost. Buying a node is permanent and
belongs to the player's account. Blocks and tools become **blueprints** at the Drafting Table; licenses and
perks (Merchant License) apply to the account directly.

## What to build

### 1. Block: Almanac Lectern
- Shapeless recipe: Lectern + Book + Gold Ingot + Paper. Always craftable (Tier 0, like the Basic Exchange).
- Right-click opens a book-style container screen with **three tabs: Upgrades, Guides, Quests**.
  There is deliberately **no records/net-worth view** here (that's a Tier 5 purchase, Digital Record Keeping).
- Breaking the block loses nothing: progress is stored per player, not in the block.
- Placeholder art is fine (generated textures like the Basic Exchange's). Add to the creative tab.

### 2. Block: Drafting Table
- Shapeless recipe: Crafting Table + 3 Paper + Iron Ingot. Always craftable (Tier 0). Creative tab.
- **Only the three Tier 0 blocks have vanilla recipes.** Every other mod block/item is made here. No recipe JSON
  for them, so a vanilla crafting table can't make them.
- Stonecutter-style list screen: all blueprints, unlocked ones selectable, locked ones greyed out with
  "Unlock at the Almanac". Selecting one shows its materials with have/need counts from the player's inventory.
  Buttons **Craft ×1** and **Craft max**; the result goes to an output slot (or the inventory if the slot is full).
- Server checks the player's unlock set and materials on every click; the client only displays.
- Blueprints are data (`exchange-core/src/main/resources/realisticmarkets/blueprints.csv` or similar):
  `result, node, material:count...`. Materials may be vanilla items or components.
- Tier 1 blueprints (placeholders; results are items/blocks that are **placeholders until M3** gives them
  behavior, register them now so the loop is playable):

| Blueprint | Node | Materials |
|---|---|---|
| Bill Clip | `bill_clip` | 2 Leather + 1 Brass Fittings |
| Price Board | `price_board` | 4 Oak Planks + 1 Glass Pane + 2 Brass Fittings + 1 Ink Bottle |
| Trade Route Crate | `trade_route_crate` | 6 Planks (any) + 2 Iron Ingots + 2 Brass Fittings + 1 Ledger Paper |

### 3. Components (buy-only items)
- Register **Ledger Paper, Ink Bottle, Brass Fittings** (Tier 1) as plain items. No recipes, no loot, not
  sold by villagers: the Dealer is the only source (plus creative). Tier 2+ components come with their tiers.
- Add them to `dealer_catalog.csv` in a new group **`components`**:

| Component | Fair value | Depth | Spread |
|---|---|---|---|
| Ledger Paper | $4 | 64 | 40% |
| Ink Bottle | $6 | 48 | 40% |
| Brass Fittings | $10 | 32 | 40% |

- Add an **optional per-item `spread` column** to the catalog (`DealerCatalog`/`MarketSpec`), falling back to
  `DealerParams` spread. Merchant License still applies: licensed spread for components = min(item spread,
  item spread × 12/20) or similar; pick one, document it, test it.
  **Decided:** the license scales every spread by `licensed_spread / spread` (12/20), so components go
  40% → 24% and default items 20% → 12%. Linked items (hay bale) use their base pool's spread.
  Component rows join the default catalog when the component items are registered (unregistered ids would
  show as air in the Buy tab).
- **Visibility:** the Buy tab shows the Components group (header "Components") and each component only once the
  player has unlocked a blueprint that uses it. The Sell tab still accepts them (at the wide bid) so a player can
  dump spares at a loss.
- Menu sync: the buy list is now per-player. Filter the item list in `BasicExchangeMenu` from the player's
  unlocks when the menu opens and on refresh; `GROUPS` gains `"components"`.

### 4. Core package `exchange-core/.../progression` (pure Java, unit-tested first)
- `UnlockNode(id, tier, cost cents, parents[], requiredQuest?, grants[])`, `UnlockTree` (loaded from data).
  Grants are either `blueprint:<result>` or `perk:<id>`.
- `PlayerProgress(unlocked set, quest states, stats)`: `canBuy(node)` with reasons, `buy(node)`,
  `hasBlueprint(result)`, `hasPerk(id)`.
- `Blueprint(result, node, materials)` + `Blueprints` (loaded from data), with
  `componentsVisibleTo(progress)` and a pure `craft(inventoryCounts, blueprint, times)` → how many can be made
  and what is consumed.
- **Tier gate:** a tier's first purchase requires owning ≥ half of the previous tier's nodes.
- `Quest(id, goal, reward)` evaluated from an **event stream** (`SaleEvent`, `PurchaseEvent`, `NetWorthEvent`,
  `DayRolloverEvent`, `CraftEvent`) so quests are testable without Minecraft.
- Serialization (text, like `DealerStateIO`) for per-player save files.

### 5. Content (data-driven, load from `exchange-core/src/main/resources/realisticmarkets/almanac/`)
Tier 1 nodes (costs from the design doc; tunable):

| Node | Cost | Prereq | Grants (M2) |
|---|---|---|---|
| Bill Clip | $40 | — | blueprint `bill_clip` (+ Brass Fittings become buyable) |
| Price Board | $75 | — | blueprint `price_board` (+ Brass Fittings, Ink Bottle) |
| Merchant License | $150 | quest 2 "Meet the Spread" | perk `merchant_license` → Basic Exchange spread 20% → 12% for this player (already supported: `licensed` param) |
| Trade Route Crate | $250 | — | blueprint `trade_route_crate` (+ Brass Fittings, Ledger Paper) |

Quests 1–8 (rewards are small dollar payouts or a discount):

| # | Quest | Goal (event-based) | Reward |
|---|---|---|---|
| 1 | First Sale | any sale at a Basic Exchange | $5 |
| 2 | Meet the Spread | buy an item, then sell the same item back | $5 + Spread guide |
| 3 | Flooding the Market | sell ≥256 of one item within one in-game day | $10 + Price Impact guide |
| 4 | Patience Pays | sell an item again after its bid recovered to ≥90% of fair value, having earlier pushed it below 70% | $15 |
| 5 | Diversify | earn ≥$20 from each of three item groups in one in-game day | $25 |
| 6 | Bookkeeper | reach $250 net worth (cash + goods at Dealer bid; lectern announces it) | $10 |
| 7 | Two Markets | *(needs Trade Route Crate, M3)*: define now, leave unreachable | $40 |
| 8 | Save It | hold $500 in cash at once | 10% off Bank Vault (store as a discount perk) |

Consider a 9th, "Make or Buy": craft your first blueprint at the Drafting Table ($5 + Input Costs guide).

Guides: 150–250 words each, plain language, one real-world parallel. First five: Money & the Dealer,
The Spread, Price Impact, Recovery & Patience, Diversification (sixth if quest 9 is added: Input Costs).
Use the player's own numbers where easy ("You sold 256 wheat for $72.82…"). Guides unlock with their
node/quest; readable in the Guides tab and "tear out" as a vanilla written book item.

### 6. Mod wiring
- `ProgressionService` (like `DealerService`): per-player `PlayerProgress`, saved to
  `<world>/realisticmarkets/players/<uuid>.txt` atomically on change + on stop. Or Fabric data attachments:
  verify with `./scripts/dev.sh api --find Attachment --fabric` before choosing.
- Emit events from `BasicExchangeMenu.sell/buy` (item, qty, cents, group, day) and from the Drafting Table
  craft (result, times).
- Paying for nodes: `Wallet.pay(player, cents)` (bills in inventory). Quest cash rewards: `Wallet.give`.
- Merchant License: pass `licensed = progress.hasPerk("merchant_license")` into the Dealer calls in the menu.
- License reissue (physical copy for a small fee) is **not** in M2; note it for M3.
- **Decided:** per-player text files (`ProgressStateIO`), not Fabric attachments, matching the Dealer's save.
  A file that fails to parse is moved aside as `<uuid>.broken-<time>` rather than overwritten.
- **Decided:** quest 4's 70%/90% thresholds compare the Dealer's *market* (mid) price to fair value, the
  "Market" and "Normal" rows the player sees. An untouched bid already sits at 90% of fair value.

### 7. Balance check
Add `sim progression`: a scripted player farming a mix of items, completing quests 1–6, buying Tier 1 nodes
and the components to craft one of each Tier 1 blueprint; report game-hours to afford all of Tier 1 including
components. Design target: **about 2 hours** of play. Also report what share of Tier 1 spending goes to
components (target: noticeable but under ~25%).
